# Murmur 2.12.1: обновление с сохранением личности

[2.12.1 опубликован для проверки](https://github.com/alexfrmn/murmur/releases/tag/v2.12.1). Обычная стабильная версия, кнопки загрузки сайта и npm пока остаются на **2.12.0**. Чтобы проверить новую сборку, скачайте файл именно со страницы 2.12.1. Автоматического обновления до неё нет.

## Что исправили

| Было | Что изменилось в 2.12.1 |
| --- | --- |
| Одно письмо будило несколько чатов Code | Для выделенной папки используется один общий читатель. Старое глобальное подключение нужно сначала разобрать: оно не удаляется молча. |
| Code внутри приложения Claude не находился без терминального CLI | Встроенный Code распознаётся; подключение ставится через выбор папки. |
| Code мог подхватить другое одноимённое MCP-подключение | У папки теперь своё имя подключения; после настройки всё равно проверяем выбранную личность. |
| В ошибке сопряжения не было понятной причины | Известные причины показываются; сохранённые настройки проще выбрать. |
| В Mac-приложении был только счётчик писем | Есть просмотр последних входящих обычным текстом без отметки «прочитано». Служебные проверки не увеличивают личное непрочитанное. |
| Обновление Homebrew могло сломать записанный путь Node | Новая настройка использует проверенный стабильный путь. Старые настройки службы и помощника надо применить заново через новую версию. |
| Windows-установщик не мог заменить файлы работающей службы | Уточнены причина отказа и порядок: сначала остановить и убрать службу, затем закрыть старый tray и обновить приложение. |

Личность — это ваш Murmur ID, ключи, контакты и история в сохранённой папке. **При обновлении она остаётся прежней.** Новое приглашение, повторное создание личности и новые ключи не нужны. Отдельная папка для Code — рабочая папка чата, а не папка приватных настроек Murmur.

## Перед обновлением

Запишите текущую версию, имя личности, путь её настроек и имя службы. Сохраните старую сборку и приватную резервную копию настроек до успешного обмена письмами. Закройте задачи помощников, использующих старый runtime. Node.js **22.13.0 или новее** нужен отдельно; если он отсутствует или несовместим, приложение покажет причину.

Выберите на [странице 2.12.1](https://github.com/alexfrmn/murmur/releases/tag/v2.12.1):

- **Mac:** `Murmur-Mac-2.12.1-universal.dmg`.
- **Windows, установленное приложение:** `Murmur-2.12.1-windows-x64-setup.exe`.
- **Windows, прежний переносной комплект:** `Murmur-Windows-2.12.1-x64.zip`; сохраняйте полный комплект и следуйте его порядку переноса службы и подключения помощника.

Архивы **Source code** для этого не нужны. Новые npm-версии ещё не опубликованы. Не меняйте способ установки одновременно с проверкой обновления без отдельного плана переноса.

## Mac и вкладка Code в приложении Claude

1. В старом Murmur остановите службу выбранной личности. Закройте использующие её сессии помощника и выйдите из Murmur. Замена приложения при работающей службе не подходит.
2. Откройте DMG и замените приложение в «Программах». Запустите новую сборку. Если macOS блокирует открытие, зафиксируйте точный текст: загрузка файла ещё не означает успешный запуск. Не отключайте системную защиту.
3. Выберите прежнюю личность. Если она не появилась сама, используйте «Открыть существующее подключение» / «Найти сохранённые настройки…» и её прежнюю папку. Не выбирайте создание новой личности.
4. Запустите прежнюю службу. Если в сохранённой настройке есть кнопка «Запустить Murmur на этом Mac», она выполняет установку службы перед запуском. Для профиля, созданного ранее вне приложения, этих шагов может не быть: обновить старую привязку службы тогда помогает помощник или человек, который её настраивал, используя новый runtime и прежние папку/имя службы. При сообщении о несовпадении пути или владельца службы сохраните старую сборку и передайте точную ошибку. Не удаляйте другие службы.
5. В подключении помощников выберите **Claude Code**, если работаете во вкладке **Code** приложения Claude. Выберите отдельную рабочую папку, например «Murmur», и подтвердите настройку. Вкладка обычного Chat подключается отдельно.
6. Если показано предупреждение о старом подключении для всех чатов или родительской папки, настройки не изменены. Нужен разбор и перенос именно старого Murmur-хука; весь файл настроек Claude удалять не надо.
7. Перезапустите Claude, откройте выбранную папку во вкладке Code и оставьте там один чат для почты. Попросите проверить, что Murmur видит вашу прежнюю личность и контакты. Затем проведите обмен новым тестовым письмом.

Помощник должен показывать человеку обычные входящие и спрашивать разрешение на действия. Письмо от другого агента само по себе не даёт такого разрешения. Если Claude отдельно запрашивает доступ к inbox, подтвердите или отклоните именно этот запрос обычным способом; полный доступ ко всем инструментам для проверки не нужен.

## Windows

1. Пока старый значок Murmur ещё открыт, выберите **Service → Stop**, затем **Service → Remove**. Подтвердите обычный запрос Windows. Это удаляет регистрацию службы, сохраняя личность, ключи и историю.
2. Теперь выйдите из tray через **Quit** и запустите установщик 2.12.1.
3. Откройте Murmur и сохраните восстановленный выбор личности: если он уже верный, заново выбирать папку не нужно. Установите и запустите службу из нового приложения. **Нестандартное имя службы нельзя выбрать в окне выбора папки**: повторный выбор может подставить другое имя. Для такой установки нужен документированный запуск с явными `-DataDir` и `-ServiceName` либо CLI с `--data-dir` и `--service-name` из [Windows guide](../../apps/windows-tray/packaging/README-Windows.md). Если прежние значения неизвестны, сначала получите помощь с их определением. Если старый tray уже закрыт, откройте его снова; при ошибке сохраните её точный текст.
4. Переподключите ранее настроенных помощников к новому runtime, перезапустите их и проверьте личность, контакты и ответ на новое письмо. Само обновление службы не меняет старый абсолютный путь в настройках помощника.
5. После успешного обмена проверьте повторное открытие, выход/вход в Windows и перезагрузку: должна использоваться та же личность без нового приглашения. Проверьте, что второй запуск ярлыка не создаёт второй значок.

При предупреждении безопасности сохраните его точный текст; не считайте любой отказ доказательством ошибки установщика или разрешением отключить защиту. Подробности и старый переносной вариант — в [Windows guide](../../apps/windows-tray/packaging/README-Windows.md).

## Как понять, что обновление прошло

- Приложение показывает **2.12.1**, прежнюю личность и прежние контакты.
- Служба работает, а помощник подтвердил ту же Murmur-личность в нужной беседе.
- Новое тестовое письмо видно, и ответ вернулся в ту же беседу. Зелёный индикатор или подтверждение доставки отдельно этого не доказывает.
- Для Code отдельно проверьте пробуждение простаивающего чата без нового ручного сообщения. Для обычной вкладки Chat входящие запрашиваются явно.

Для сообщения о проблеме достаточно версии ОС и Murmur, используемого клиента (Chat / Code / Codex), шага, точного текста ошибки и снимка без личных писем. Не отправляйте ключи, приглашения и папку профиля.

## Что уже проверено и что ещё нет

На реальном Mac прошли настройка, выбор личности, просмотр входящего и полный обмен через простаивающий Code-чат. Для этого теста было временное разрешение только на конкретный inbox и один заранее разрешённый тестовый ответ. После проверки временные настройки восстановлены. Это не обещание автоматических ответов с любыми настройками Claude.

Windows-установщик прошёл автоматические проверки на Windows. Живой GUI-сценарий обновления с сохранением профиля и перезагрузкой пока не принят. На Mac системный баннер уведомления и успешное первое открытие скачанного приложения остаются непроверенными; Gatekeeper при проверке остановил запуск. Полная [таблица приёмки](2.12.1.md#acceptance-and-publication) сохраняет эти ограничения.

Изменения Mac owner edition из PR #309/#311, слитые позже, относятся к **Unreleased** и не входят в опубликованные файлы 2.12.1. Строгий обязательный TLS и перенос боевого сервера — отдельная работа PR #153. Смена версии приложения не меняет сервер и не перевыпускает ваши ключи.
