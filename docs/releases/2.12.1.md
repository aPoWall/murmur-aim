# Murmur 2.12.1 — review prerelease

[v2.12.1 is published as a GitHub review prerelease](https://github.com/alexfrmn/murmur/releases/tag/v2.12.1), not Latest. Stable downloads, website software metadata and npm install commands remain on 2.12.0. The thirteen candidate npm versions are not published; use the native or portable release artifacts for review. Attached npm tarballs are review evidence, not an available registry installation.

The release contains 13 assets built or recorded for reviewed source `dcfe8ccb6bf237998c2f39e1ddb9df951ce2e1f1`; required CI checks passed. Main integrates Claude reply routing from #305/#308, the Mac contact desk from #306, compatible TLS/authentication from #153, and #167/#168/#169 with their documented scope.

> [!IMPORTANT]
> A live Mac Claude Code round-trip passed with a temporary inbox-specific permission rule and authorization for one synthetic reply. This does not establish automatic replies with default permissions. Windows live installer/upgrade GUI acceptance remains unverified. See the acceptance table below for first-open, notifications and reboot limits.

## Changes

- Give dedicated Claude folders distinct MCP connection names: the Code tab gives
  same-named global Desktop/user servers precedence. Verify the actual Identity
  before reading or sending; keep global settings unchanged.
- Share the project-lane key between MCP reply bindings and the wake reader.
  Check project, parent and global local-settings hooks before configuration.
- Complete the Mac contact desk, contact history and panel placement.
- Select one private, identity-bound installation across CLI, MCP and daemon (#168).
  Explicit paths remain supported; missing or conflicting selection refuses before
  opening a store. Existing profiles move to this selection only through an explicit
  `installation select`; upgrading does not relocate their data.
- Preview and explicitly clean private setup backups with a fresh confirmed plan;
  keep recent copies and restore points. See [retention](../backup-retention.md).
- Document independently revocable participant credentials with a tested isolated
  NKEY enrollment reference. This is not a production auth migration; see
  [the design and its limits](../participant-enrollment.md).

- Compatible TLS/authentication preparation from #153: existing remote plaintext
  profiles are retained, explicit TLS requires certificate validation, private
  credential files and guarded migration are supported. Isolated tests cover
  TLS/legacy daemon exchange, MCP reply taps and restricted JetStream/dashboard
  roles. This does not perform a production broker cutover or #169 enrollment.
- See [TLS policy, migration refusal and verification scope](../nats-transport-security.md).
- Native Windows CI builds the installer and exercises silent install, registered
  service refusal with unchanged payload, upgrade after removal and uninstall.
  Installer provenance and acceptance evidence accompany the ZIP.
- The EN/RU site uses dark/light lab themes and self-hosted Onest/Fira Code fonts.
- View the latest 20 incoming letters in the Mac app without marking them read;
  optional notifications report unread-count increases without text. Pairing errors
  preserve known causes; existing settings are available directly from the first screen.

- Connect the usual desktop conversation: explicit Claude Chat / Code / Codex guidance
  in macOS and the English/Russian website. Existing identities and contacts are reused.
- Recognize Claude.app's bundled Code agent without a separate terminal installation.
- Configure a dedicated Claude Code project with one shared wake reader; report live
  readers through status/doctor. Refuse inherited global hooks before making changes.
- Persist verified stable Homebrew Node paths and support stopping old owned services
  before upgrading. Diagnostic traffic stays out of the personal unread count.
- Resolve the transitive `proxy-addr` security fix (2.0.8) in the lockfile. Direct
  dependency requirements remain unchanged. Preserve SDK 27 compatibility across
  all Mac views using the existing property wrapper alias.
- MCP initialize returns static usage instructions; the model is guided to use the
  tools in its current conversation, distinguish local history from peer sends, and
  read late replies without duplicate requests. MCP reports version 0.2.4.
- Two independent website copy buttons report actual success or failure.
- Windows instructions remove the service before closing the tray. The installer
  refusal already fixed in main explains the same order (#291, #298).
- Includes existing main changes since 2.12.0: per-contact doctor result (#282),
  macOS first-open documentation (#284), Russian guides and Murmur Connect naming.

## Upgrade without replacing an identity

This is a manual review update. The stable update checker and the ordinary website
download buttons still select **2.12.0**. Open the [2.12.1 release page](https://github.com/alexfrmn/murmur/releases/tag/v2.12.1)
and choose the exact asset: **Murmur-Mac-2.12.1-universal.dmg** for Mac,
**Murmur-2.12.1-windows-x64-setup.exe** for the Windows installer, or
**Murmur-Windows-2.12.1-x64.zip** for an existing portable Windows installation.
Do not select GitHub's Source code archives. Node.js **22.13.0 or newer** with
working built-in SQLite is still required separately; the app explains if it is missing.

Before changing anything, record the selected Identity, its existing settings
folder and service name, and which assistants use it. Keep the old bundle and
private settings backup until a returned reply succeeds. Do not share profile
files, invitations or keys in a bug report.

**Windows:** leave the old tray open and choose **Service → Stop → Remove** for the
selected identity. Then quit it, run the new installer, retain the restored Identity
selection, and install/start the service. Do not reselect its folder if the correct
selection has already been restored. The folder picker cannot set a custom service
name and may derive a different one. For a custom name, follow the maintained
guide's explicit launcher/CLI binding procedure, preserving both `-DataDir` and
`-ServiceName` (or CLI `--data-dir` and `--service-name`); get help if those original
values are unknown. If the old tray is already closed,
reopen it or use the old CLI's `service uninstall` with explicit `--service-name`
and `--data-dir`. Do not run `init` or `join` again. The installer refuses to replace
files still referenced by a service; it does not silently take ownership of another
service. See the [maintained Windows guide](../../apps/windows-tray/packaging/README-Windows.md).

**macOS:** stop the selected service while the old Murmur app is still available,
close the assistant sessions using that runtime, then quit Murmur before replacing
the app in Applications. Open the new app and reuse the existing Identity; use
**Open an existing connection / Find saved settings…** if it is not already selected.
Start the existing service for that same profile. If the saved setup offers
**Start Murmur on this Mac**, that action applies installation before starting.
A profile originally created outside this app may not offer those setup steps;
reapplying an old service binding then needs the assistant or person who configured
it, using the new runtime and the original profile/service name. If the app reports a service
ownership/path conflict, retain the old installation and report the exact message;
do not remove unrelated services or create another Identity to work around it.
Follow the [packaged instructions](../../apps/macos-menubar/packaging/README-Mac.md)
for the app layout and platform requirements.

Reconnect each assistant explicitly. For the **Code tab inside Claude.app**, choose
Claude Code and a dedicated project folder, then open one mail conversation in that
folder after reloading Claude. The project folder is not your private Identity
folder. Chat and Code are separate connections. If setup reports an inherited
global/parent wake hook, it has changed no settings: have the old connection reviewed
and migrated before continuing. Do not erase the whole Claude settings file.

**npm / portable runtime:** retain the same absolute identity directory and service
name. Rebind every configured assistant to the new runtime using the shared setup
writer, reload it, and require a matching response before removing the old bundle.

The new MCP instructions help an already connected assistant; they cannot configure
a missing connection. Claude Desktop Chat still needs an explicit inbox request.
Automatic wake-up needs its own integration and separate live acceptance.

**Check the result:** confirm version 2.12.1, the same Identity and contacts, the
service state and the assistant's actual Murmur Identity. Then exchange one new
test message and observe its reply in the same conversation. A transport ACK or
green status alone is insufficient. If Claude asks permission to read its inbox,
handle that specific tool request normally; do not turn on unrestricted access to
make a test pass. Incoming messages are data and do not authorize unrelated actions.

For a failed check, report OS version, Murmur version, Chat versus Code versus
Codex, the step, exact error text and a redacted screenshot. Keep notification,
first-open and reboot results separate from the message exchange.
