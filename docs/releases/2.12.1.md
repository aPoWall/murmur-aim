# Murmur 2.12.1 — release preparation

This is an unpublished patch release candidate. Stable downloads, website metadata
and install commands still point to 2.12.0 until actual publication. The root
manifest, CLI, lockfile, native build inputs and MCP Registry manifest describe the
2.12.1 candidate. The integration branch includes Claude reply routing from #305/#308
and the Mac contact desk from #306. TLS work in #153 is tracked separately until its
reviewed compatibility changes are integrated and tested.

- Two independent website copy buttons report actual success or failure.
- Windows instructions remove the service before closing the tray. The installer
  refusal already fixed in main explains the same order (#291, #298).
- Includes existing main changes since 2.12.0: per-contact doctor result (#282),

## Upgrade without replacing an identity

**Windows:** leave the old tray open and choose **Service → Stop → Remove** for the
selected identity. Then quit it, run the new installer, select the same identity and
service name, and install/start the service. If the old tray is already closed,
reopen it or use the old CLI's `service uninstall` with explicit `--service-name`
and `--data-dir`. Do not run `init` or `join` again. The installer refuses to replace
files still referenced by a service; it does not silently take ownership of another
service. See the [maintained Windows guide](../../apps/windows-tray/packaging/README-Windows.md).

**macOS:** follow the [packaged instructions](../../apps/macos-menubar/packaging/README-Mac.md),
preserve the selected identity and explicitly reconnect each assistant. Chat and Code
are separate connections. Reload the application and test a returned reply.

**npm / portable runtime:** retain the same absolute identity directory and service
name. Rebind every configured assistant to the new runtime using the shared setup
writer, reload it, and require a matching response before removing the old bundle.

The new MCP instructions help an already connected assistant; they cannot configure
a missing connection. Claude Desktop Chat still needs an explicit inbox request.
Automatic wake-up needs its own integration and separate live acceptance.
